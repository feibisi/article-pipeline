# article-pipeline 全系统核查报告

> 日期：2026-07-22 | 核查方：elementary（5 路并行子代理，全部证据带 file:line / DB 记录）
> 触发：主人判定管线全部产出不合格并删除，要求核查整个文章系统。

## 一句话结论

这套系统把"能产出通过文本统计检查的文字"误当成了"能产出值得发布的文章"。四个月工程围绕一堆表层代理指标堆砌，而真正难的问题——判断什么值得写、写得对不对、有没有新增价值——从没被解决，反而被一套永远亮绿灯的指标掩盖了。**主人删稿的直觉完全正确；这份报告解释了机器为什么看不到人一眼就看到的东西。**

## 五路核查发现

### 1. 产出质量（实读全部 10 篇）
- 系统性事实错误 + 编造数据，非偶发：杜撰常量 `WP_FATAL_ERROR_HANDLER`、跑不通的 Docker/Nginx 代码、讲反的 ctime、把缓存命中率打到 0 的配置、"systemd 毫秒级调度"神话；无来源精确统计遍地。
- 选题零存在理由 + 零去重（task 98/99 是同一关键词产出的双胞胎）。
- 同质化 AI 骨架 + 惊悚 hook 腔（"你打开一个 X，看起来只是一瞬间的事"）。
- 零品牌契合甚至反噬：task 56 推 Wix/Squarespace/Gemini 等竞品；task 61 给真实产品 WPDate 编造客户证言和转化数据——品牌负债。
- **根因链**：知识标注注入"话题盲"——systemd 文章被注入《计算机组成》CPU 公式 + 《动画节奏》内容，"毫秒级"错话即由此而来。本该差异化的 cocobook 注入，反而在制造自信的错误。
- 判决：无一篇可按现状发布。平均"大改能发偏废稿"。

### 2. 质量门控标定
- **总分公式 `compute_overall_score` 不含 value_density**（review/__init__.py:456）——唯一反 slop 的指标被排除在放行决策外。
- 冒烟枪（review_log id 248-251）：`overall_score 8.9-9.2, pass=True`，同一条记录 `judgment_density/source_depth/counter_intuitive 全为 0`。三个衡量洞见的维度全 0，系统照样判"优秀"。
- `unique_info_ratio` 恒 10/10：ddg_results 默认空（__init__.py:792），空对照集里所有 claim 判为独占。
- 全部指标是正则/计数/句长方差，无一做语义或价值判断。humanizer 只保证"读着不像 AI"，永远保证不了"值得读"。
- 修复：调参救不了，需引入 LLM-as-judge 语义评审 + 已有代表作比对，把放行决策权交给语义层。

### 3. 级联编译成色
- **COMPILE 是死管线**：组装好的最终提示词存入 DB 后从不被写作层读取（pipeline.py:394-397 vs writer.py:565-570），writer 退回啃截断到 8000 字符的原始 research_note。
- PROSODY 装饰：范本加载了但从不进写作层（writer 用 `_extract_samples(research_note)`）。
- FRAMEWORK 回退逻辑是假的：读了 preferred/fallback 变量直接丢弃（framework.py:142-145）。
- 真实有效仅 STYLE 层（五维坐标直连写作提示词）+ SYNTHESIS/OUTLINE 两次 LLM 调用。前面综合的结构化努力在进入笔端前被稀释。

### 4. 品类资产
- 21 品类契约文件齐全，但真正完备仅 **2/21**（tutorial、opinion），基本可用 3 个，其余 **16 个共用同一 generic 三段空壳**（framework.yaml md5 相同，写着"待补充品类特定方法论"）。
- 每品类实际只有 1 篇真实范本，另 3 个槽是全局共享僵尸占位文（正常流程不加载）。
- manifest 声明的专属方法论名对 16 个品类是装饰，status 全标 validated 名不副实。
- **高频品类（wp-tech/guide/product-launch/marketing）恰恰全落在最弱的 16 个里。**

### 5. 系统完整性
- 自动流程走到 `reviewing` 就停，**从不调 publish**。发布只能手动 CLI 或未接线的 web UI。
- 那 6 篇 done 是测试期假成功：`published_url` 从没写进正式列（db.py:152-179 列/blob 分裂 bug），生产站对应 URL 全 404；translate 桥在 returncode==0 时误判成功。
- 调度器 systemd timer 存在但 disabled/inactive，从没自动跑过。7-01 后无产出=本来就没自动调度，7-01 是人工测试当天。
- 选题唯一来源人工 add，无自动选题。人一停，管线空转——产出停滞的上游根因。
- "114 测试全绿"当前环境不可复现（131 collected, 1 error，bs4 未装）。约 35% 测试刷绿；对"产出+发布一篇文章"有意义的覆盖≈0。`test_db.py:96` 只测 published_at 不测 published_url，固化了列 bug。
- 孤儿代码：visual.py / social_card.py / screenshot.py 零 import；review_server.py 文档命令不存在。

## 什么是真能用的（公允记录）
- STYLE 五维坐标系统（真映射到具体写作约束，直连生成）。
- DB / CLI 骨架、genre_rules.yaml（21 个真实有区分度）、mermaid 渲染。
- SYNTHESIS 的结构化理解本身（只是下游没接好）。

## 决策待定
见会话结论。三条路：(A) 诚实封存；(B) 激进重构、重定目标为"人辅助的少而精"+ LLM-judge 放行 + 修选题/事实纪律；(C) 只修具体 bug（不推荐，治标）。
